## Mandate

Read-only and non-blocking. Surface candidate repositories; adopt nothing.

## Hard filters — a repo must clear all four

1. **License is OSI-approved** and permits commercial use and modification. MIT,
   Apache-2.0, BSD. Reject AGPL, SSPL, and "source available" — a viral or field-of-use
   license is incompatible with a project that may ship.
2. **Zero new packages.** The repo must teach a *pattern* implementable in the existing
   stack. If the only value is the library, it is rejected.
3. **$0.00 compatible.** No required paid endpoint, no mandatory hosted service.
4. **Maintainable.** Recent commits, an issue tracker that responds, no abandoned
   single-author experiments presented as infrastructure.

## Weighting for prioritization

Stars are a popularity signal, not a quality signal — a viral toy outranks a maintained
primitive. Prioritize in this order:

1. **Recency of meaningful commits** (not README bumps).
2. **Whether the project dogfoods the pattern** — self-hosted use beats a paper.
3. **License clarity.**
4. Stars, as a tiebreaker only.
5. Issue-to-commit ratio, as a health signal.

Red flags that disqualify regardless of stars: no license file, an explicit
"experimental alpha" with no security posture, or a maintainer who writes that their code
was mostly generated by an agent **and has not been audited**.
